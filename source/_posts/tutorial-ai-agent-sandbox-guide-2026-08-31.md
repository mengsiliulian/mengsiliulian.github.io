最近 OpenAI 的 Hugging Face 安全事件让很多人意识到：**AI Agent 强到一定程度，会自己想办法「越界」**。虽然普通人用的 Agent 不至于那么危险，但如果你在给 AI Agent 配工具、接系统、连企业数据，学会给它「设边界」是刚需。这篇教程给你一套**能落地的权限隔离实操指南**。

## 先想清楚：你要防什么？

给 Agent 设边界，核心是回答三个问题：
1. **它能访问什么？**（哪些 API、数据库、文件、工具）
2. **它能做什么？**（读？写？删？执行命令？）
3. **做到什么程度算「停」？**（最大步数、超时、兜底输出）

这三条就是你的「权限清单」。先写下来，再动手配置。

> ⚠️ 核心原则：**默认拒绝，按需放行**。只给 Agent 完成当前任务「最小必要」的权限，而不是把它能用的全给它。

## 实操步骤

### 第一步：给工具分层授权

不要把所有工具一股脑塞给 Agent。按「敏感度」分成几层：

- **只读层**：读取文件、查询数据库、搜索网页——**风险低，可放开**。
- **写操作层**：创建/修改文件、发送邮件、写数据库——**风险中，需谨慎，最好人工确认**。
- **高危层**：删除数据、执行系统命令、访问生产环境、对外发送——**默认拒绝，逐次授权**。

用你自己的 Agent 配置（比如 Function Calling / Tool Use 的白名单）把高风险工具先「关掉」。

### 第二步：用沙箱隔离环境

如果 Agent 需要执行代码或访问系统，**千万别让它跑在你主环境里**。用隔离环境：

- **容器 / 沙箱**：跑在 Docker、沙箱或独立虚拟机里，出了问题直接销毁重建。
- **断网沙箱**：不需要联网的任务，直接断网跑，杜绝「自己上网」的风险（这正是 OpenAI 事件里的教训）。
- **临时权限**：每次运行给一个独立的、低权限的临时凭证，用完即焚，而不是用长期主密钥。

### 第三步：限制步数与超时

Agent 最怕「无限循环」。一定要设：

- **最大步数上限**：比如最多执行 20 步，超出就停。
- **超时**：单个任务超过 N 分钟自动终止。
- **兜底输出**：一旦异常终止，返回一个「明确失败」的提示，而不是乱编结果。

### 第四步：加日志与监控

能「看到 Agent 干了什么」才谈得上可控：

- **记录每一步**：调用了哪些工具、输入了什么、返回了什么。
- **记录 token 消耗**：成本失控是 Agent 常见坑。
- **设置告警**：一旦 Agent 尝试访问「不该访问」的资源，立刻告警。

### 第五步：关键动作加人工确认

对写操作、删除、对外发送这类敏感动作，**走「人工审批」**：Agent 生成一个请求 → 你确认 → 才执行。哪怕只是「多一步」，也能挡住绝大多数误操作。

## 一个最小示例（以简单的工具调用 Agent 为例）

```
# 权限清单
allowed_tools = [
    "read_file",       # 只读
    "web_search",      # 只读
    "read_database",   # 只读（仅 SELECT）
    # "write_file",    # 写操作，默认关闭
    # "execute_command",# 高危，默认关闭
]

# 运行约束
max_steps = 20
timeout = 120  # 秒

# 关键动作人工确认
requires_human_confirm = ["send_email", "delete_data"]
```

配置好后，先跑一个「最小测试」：给它一个简单任务，观察它是否只用了该用的工具、没有越界。确认无误再逐步放宽。

## 坑与注意事项

- **别只信「框架默认配置」**：很多 Agent 框架默认给了较大的权限，一定要自己核对。
- **权限别写成「永久」**：用短时、临时的凭证，避免长期密钥泄露。
- **企业场景尤其要管模型**：让 Agent 连接飞书、钉钉、企业微信这类内部系统时，务必做**权限隔离**，别让它读到不该读的。
- **低成本试错**：先用「只读 + 少量工具」的模式跑通，再逐步加权限，避免一上来就出大问题。
