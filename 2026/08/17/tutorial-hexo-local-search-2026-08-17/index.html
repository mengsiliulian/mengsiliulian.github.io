给 Hexo 博客加「站内全文搜索」：无外部服务的本地方案

博客文章多了之后，「站内搜索」几乎是刚需。但很多搜索插件要依赖第三方服务（如 Algolia），既要注册、又可能涉及额度与隐私。这篇教程给你一套纯本地、无外部依赖的站内全文搜索方案，适合 Hexo 静态站。

方案原理

核心思路：把全站文章内容在构建时生成一份可检索的索引文件，前端用 JavaScript 在本地完成匹配，不发任何请求到外部。

  • 构建时：用一个 Hexo 插件，把所有文章的标题、标签、分类、摘要、内容导出成一份 JSON 索引。
  • 运行时：访问了一个搜索页面，前端脚本加载这份 JSON，在浏览器里做关键词匹配和结果渲染。
  • 优点：无外部服务、无额度限制、数据不出站、部署简单。

具体步骤

1. 安装 / 启用生成索引的插件

不同的搜索插件生成索引的方式不同。以「生成本地 JSON 搜索数据」为思路的 Hexo 插件为例（名字以你能找到的最新插件为准）：

然后在 _config.yml 里按插件文档配置要索引的字段（通常包含 title、tags、categories、content 等）。

2. 新建搜索页

在 source 目录下新建一个搜索页（如 search/index.md），front-matter 里开启 comments: false（搜索页不需要评论），并预留一个搜索结果容器：

3. 写前端脚本

在你的主题里（或页面里）引入一段 JS：监听输入 → 加载索引 JSON → 对标题 / 标签 / 内容做包含匹配 → 渲染结果列表。匹配时建议：

  • 对关键词去空白、转小写再比较，兼容大小写。
  • 标题命中优先展示，内容命中排在后面。
  • 结果数量做上限，避免一次性渲染过多。

4. 构建验证

到 public 目录确认索引 JSON 已生成、搜索页面能正常加载，再本地 hexo server 试一下，最后部署。

坑与注意事项

  1. 索引里别带过多内容：如果每篇文章全文都导进 JSON，索引文件会偏大，首屏加载会变慢。可按需只索引标题 + 摘要 + 标签。
  2. 中英文混合匹配：中文分词是难点，简单方案用「字符串包含」即可满足大多数场景；追求更好的效果可引入轻量中文分词，但会增加复杂度。
  3. 与主题的兼容性：不同主题的脚本加载方式不同，先看主题文档，避免脚本被主题覆盖或重复加载。
  4. 更新索引：每次新增文章都要重新 hexo generate，或使用持续集成（如 GitHub Actions）构建时自动生成。

小结

「构建时生成本地 JSON 索引 + 前端匹配」是一套干净、省心、不依赖第三方的站内搜索方案。它牺牲了一点「智能分词」，换来的是零外部依赖、无额度焦虑、数据完全自持——对大多数个人博客完全够用。
